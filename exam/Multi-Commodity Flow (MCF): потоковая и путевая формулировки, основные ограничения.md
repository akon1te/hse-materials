# Multi-Commodity Flow (MCF): потоковая и путевая формулировки, основные ограничения

## Набор обозначений

* Ориентированный граф: (G=(V,E)).
* Множество товаров (коммодити): (K).
* Для товара (k\in K): источник (s_k), сток (t_k), спрос (d_k>0).
* Пропускная способность ребра (e\in E): (u_e\ge 0).
* Линейная стоимость (базовая постановка): (c_{e,k}) — стоимость единицы потока товара (k) на ребре (e).

---

## 1) Потоковая (edge-based) формулировка

**Переменные**

* Поток товара (k) по ребру (e): (x_{e,k}\ge 0).

**Цель**

```math
\min \sum_{e\in E}\sum_{k\in K} c_{e,k}\,x_{e,k}
```

**Ограничения**

1. **Баланс потока** (для каждого товара (k) и узла (v\in V)):

```math
\sum_{e\in \delta^+(v)} x_{e,k} \;-\; \sum_{e\in \delta^-(v)} x_{e,k}
=
\begin{cases}
 d_k, & v=s_k,\\
 -d_k, & v=t_k,\\
 0, & \text{иначе.}
\end{cases}
```

2. **Ограничение пропускной способности ребра** (суммарно по всем товарам):

```math
\sum_{k\in K} x_{e,k} \;\le\; u_e \qquad \forall e\in E.
```

3. **Неотрицательность**:

```math
x_{e,k}\ge 0 \qquad \forall e\in E,\ \forall k\in K.
```

> **Комментарий.** Размерность переменных — (O(|E|\cdot |K|)). Формулировка проста и хорошо подходит для задач с «не слишком» большим числом рёбер и товаров.

---

## 2) Путевая (path-based) формулировка

Пусть (\mathcal{P}_k) — множество допустимых путей от (s_k) к (t_k).
Для пути (p\in \mathcal{P}*k) зададим индикатор принадлежности ребру:
[
a*{e,p} =
\begin{cases}
1, & e\in p,\
0, & e\notin p.
\end{cases}
]

**Переменные**

* Поток товара (k) по пути (p): (x^{k}_{p}\ge 0).

**Путевая стоимость** (если исходно задана реберная стоимость (c_{e,k})):

```math
c^{k}_{p} \;=\; \sum_{e\in E} c_{e,k}\,a_{e,p}.
```

**Цель**

```math
\min \sum_{k\in K} \sum_{p\in \mathcal{P}_k} c^{k}_{p}\,x^{k}_{p}
```

**Ограничения**

1. **Выполнение спроса** (для каждого товара):

```math
\sum_{p\in \mathcal{P}_k} x^{k}_{p} \;=\; d_k \qquad \forall k\in K.
```

2. **Пропускная способность рёбер** (агрегация потоков путей на ребро):

```math
\sum_{k\in K} \sum_{p\in \mathcal{P}_k} a_{e,p}\,x^{k}_{p} \;\le\; u_e 
\qquad \forall e\in E.
```

3. **Неотрицательность**:

```math
x^{k}_{p}\ge 0 \qquad \forall k\in K,\ \forall p\in \mathcal{P}_k.
```

> **Комментарий.** Число путей может быть экспоненциальным в (|V|). На практике применяют **поколение столбцов (column generation)**: стартуют с малого подмножества путей и итеративно добавляют «выгодные» пути по результатам pricing-задачи (обычно — кратчайший путь с модифицированными дуговыми весами).

---

## 3) Связь формулировок и дополнительные варианты

* **Эквивалентность.** Путевая модель эквивалентна потоковой при полном множестве путей:
  (;x_{e,k}=\sum_{p\in \mathcal{P}*k} a*{e,p},x^{k}_{p}).
* **Неразделимость потоков (unsplittable).** Если требуется вести весь товар (k) по одному пути, вводят бинарные переменные (z^k_p\in{0,1}) и ( \sum_{p} z^k_p=1), а объём делают (x^k_p = d_k z^k_p) → задача становится NP-трудной (MIP).
* **Нелинейные/фиксированные издержки.** Часто стоимость ребра включает фиксированный платёж за «активацию» (или количество ТС). Это моделируется целочисленными переменными (y_e) и связью
  ( \sum_{k} x_{e,k} \le C,y_e ), цель: (\min \sum_e f_e y_e + \sum_{e,k} c_{e,k} x_{e,k}) (см. лекцию о линеаризации).

---

## 4) Минимальный чек-лист «основных ограничений» (что помнить на экзамене)

1. **Баланс потока по каждому товару** (либо через узловые балансы — edge-based, либо через «выполнение спроса» суммой по путям — path-based).
2. **Пропускные способности рёбер** (суммарно по всем товарам).
3. **Неотрицательность** (и при необходимости — целочисленность/бинарность).
4. **(Опционально) Лимиты на использование рёбер/стоимостные фичи**: фиксированные издержки, число ТС, окна мощностей и т.п. — через дополнительные переменные и линейные связи.

---

## 5) Когда какую формулировку выбирать

* **Edge-based**: компактнее по числу ограничений, хороша при умеренном (|E|\cdot|K|); естественна для линейных затрат.
* **Path-based**: удобна для колоночной генерации, для сложных стоимостей/политик маршрутизации; полезна, когда оптимальные решения используют малое число путей на товар.
