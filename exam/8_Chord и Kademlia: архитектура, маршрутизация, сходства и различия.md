# 2) Chord и Kademlia: архитектура, маршрутизация, сходства и различия

## Chord (MIT, 2001)

**Архитектура.**

* Логическое **кольцо** идентификаторов $[0,2^m-1]$ (обычно SHA-1).
* Ключ хранится у **$successor(hash(key))$** (первый узел по кольцу с ID $\ge hash(key)$).

**Маршрутизация.**

* **Finger table** ускоряет поиск: для узла $n$, запись $i$: $finger[i] = successor(n + 2^{i-1})$.
* На каждом шаге запрос пересылается ближайшему предшественнику цели из finger table.
* Поиск: $O(\log N)$ переходов.

**Особенности.**

* Строгая кольцевая инварианта; требуется стабилизация finger-таблиц при churn.
* Теоретически аккуратен, но не оптимален по реальным задержкам.

## Kademlia (2002)

**Архитектура.**

* Пространство ID такое же $[0,2^m-1]$, но расстояние — **XOR-метрика**:
  $$
  d(a,b)=a\oplus b.
  $$
* Узел хранит **$k$-buckets** — списки узлов по «зонам» расстояний (по общему префиксу).

**Маршрутизация.**

* Итеративный поиск ближайших к цели ID: каждый шаг запрашивает несколько узлов, всё ближе и ближе к цели (параллельные запросы).
* Поиск: обычно $O(\log N)$, часто быстрее на практике благодаря параллелизму и good locality.

**Особенности.**

* Активная поддержка таблиц (ping/refresh); высокая устойчивость к динамике.
* Хорошо работает в реальных сетях (используется в BitTorrent, Ethereum, IPFS).

## Сходства и различия

| Аспект | Chord | Kademlia |
|---|---|---|---|
| Пространство ID | Кольцо $[0,2^m!-!1]$ | То же |
| Метрика | Кольцевое «следующий по часам» | XOR: $d(a,b)=a\oplus b$ |
| Структура таблиц | Finger table | $k$-buckets (по диапазонам расстояний) |
| Поиск | $O(\log N)$, последовательная навигация по finger | $O(\log N)$, параллельные запросы, быстро на практике |
| Устойчивость к churn | Требует стабилизаций | Высокая, активные обновления бакетов |
| Применения | В основном академические | BitTorrent DHT, IPFS/Libp2p, Ethereum |
