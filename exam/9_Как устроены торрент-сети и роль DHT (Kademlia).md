# 3) Как устроены торрент-сети и роль DHT (Kademlia)

**Компоненты BitTorrent.**

* **Файл `.torrent`**: метаданные (размер, список хешей фрагментов — *pieces*).
* **Пиры (peers)**: участники обмена фрагментами; **сиды** имеют полный файл, **личи** — ещё скачивают.
* **Обмен**: файл разбит на куски (обычно 256 КБ–1 МБ); используется стратегия *rarest first* (сначала редкие куски); протокол: `handshake → bitfield → request → piece`.

**Роль DHT.**

* Ключ в DHT — $info_hash$ раздачи (хеш метаданных).
* Значение — список $(\text{IP}, \text{порт})$ пиров, участвующих в этой раздаче.
* BitTorrent-клиенты используют **Kademlia-подобный DHT** вместо/вдобавок к трекерам:

  * **Поиск пиров**: запрос ближайшим к $info_hash$ узлам по XOR-метрике $d(a,b)=a\oplus b$.
  * **Хранение**: пир публикует себя у узлов, «близких» к $info_hash$.
  * Это делает сеть **полностью децентрализованной** (работает и без трекеров).
* **Magnet-ссылки** (`magnet:?xt=urn:btih:<info_hash>`): содержат только $info_hash$; всё остальное (пиры) находится через DHT.

**Итог.**

* DHT на основе Kademlia — «адресная книга» торрент-роя: быстро находит пиров за $O(\log N)$ запросов без флуда и центральных серверов, повышая масштабируемость и отказоустойчивость сети.
